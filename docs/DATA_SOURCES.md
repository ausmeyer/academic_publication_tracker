# Data sources and search behavior

Academic Publication Tracker offers eight search choices: Google Scholar, OpenAlex, Crossref, Europe PMC, PubMed, Semantic Scholar, Preprints, and DataCite. Preprints combines existing public APIs; the legacy arXiv adapter remains available for saved searches. It does not bundle a paid database subscription. Access documentation was checked on **September 14, 2026**. Provider policies, coverage, and availability can change independently of this app.

## Supported sources

| Source           | Access                                                               | Useful coverage                                                             | Citation counts                                          |
| ---------------- | -------------------------------------------------------------------- | --------------------------------------------------------------------------- | -------------------------------------------------------- |
| Google Scholar   | Free internal collection; sign-in may be requested by Google         | Displayed search results and author-profile papers                          | Displayed counts at capture time                         |
| OpenAlex         | Basic keyless access; free account/key recommended                   | Multidisciplinary publications and author profiles                          | OpenAlex citation graph                                  |
| Crossref         | No registration; optional contact email                              | Publisher-deposited DOI metadata                                            | References linked within Crossref                        |
| Europe PMC       | No registration                                                      | Life sciences, biomedical literature, and preprints                         | Europe PMC citation graph                                |
| PubMed           | No registration; optional free NCBI key                              | Biomedical literature                                                       | Not supplied by this connector                           |
| Semantic Scholar | Many endpoints work without authentication; free API key recommended | Multidisciplinary papers and author profiles                                | Semantic Scholar citation graph                          |
| Preprints        | No registration                                                      | arXiv plus preprints indexed by Europe PMC and Crossref                     | Counts retain their original index; arXiv counts unknown |
| DataCite         | No registration                                                      | Datasets, software, repository publications, and other DOI research outputs | DataCite Event Data citation relationships               |

**OpenAlex:** Current authentication documentation explicitly permits basic requests without a key. A free key increases the daily budget; API budget and pricing policies still apply. Add your own key in Settings. The connector uses bearer authentication, searches works, and resolves author-name queries to at most five author IDs. [Authentication](https://help.openalex.org/api/authentication/), [API reference and filters](https://help.openalex.org/api/llm-quick-reference/).

**Crossref:** The public REST API does not require registration. An optional contact email is sent as `mailto` to support the polite pool. Citation counts reflect deposited and linked references; they are not an exhaustive count of citations everywhere. The connector uses bounded offset paging for search relevance and direct DOI lookup. Publisher-supplied abstracts may have separate copyrights. [REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/), [Query and pagination guidance](https://www.crossref.org/documentation/retrieve-metadata/rest-api/tips-for-using-the-crossref-rest-api/).

**Europe PMC:** The public REST search API supplies core publication metadata, abstracts, citation counts, and full-text links where available. The connector uses cursor pagination and the documented `AUTH` author field. Full-text availability is taken from the provider; a link is not a guarantee that the content may be redistributed. [REST documentation](https://europepmc.org/RestfulWebService), [Search help](https://europepmc.org/Help), [Field reference](https://europepmc.org/docs/EBI_Europe_PMC_Web_Service_Reference.pdf).

**PubMed:** The connector searches NCBI ESearch and retrieves article metadata/abstracts with EFetch. NCBI permits up to three requests per second without a key and a higher default rate with a key. This app conservatively spaces NCBI calls by at least 400 ms regardless of key. Settings' contact email is not sent as NCBI's developer email. Before distributing a heavily used deployment, maintainers should follow NCBI's guidance for registering the app's tool name and a developer contact. [Usage requirements](https://www.ncbi.nlm.nih.gov/books/NBK25497/), [E-utilities parameters](https://www.ncbi.nlm.nih.gov/books/NBK25499/).

**Semantic Scholar:** Unauthenticated requests share a rate limit and can be throttled heavily. A free individual API key is recommended; the introductory authenticated rate is one request per second. The connector spaces requests by at least 1.1 seconds and uses the Academic Graph API. [API access](https://www.semanticscholar.org/product/api), [Endpoint documentation](https://api.semanticscholar.org/api-docs/graph), [Tutorial](https://www.semanticscholar.org/product/api%2Ftutorial).

**arXiv:** The connector reads the official Atom API, spaces requests by at least 3.1 seconds, and returns preprint metadata. Publication year means the first arXiv submission year. The documented search fields do not include DOI lookup; DOI mode therefore reports that limitation without issuing an approximate query. [API manual](https://info.arxiv.org/help/api/user-manual.html), [API terms](https://info.arxiv.org/help/api/tou.html).

**DataCite:** Uses the public DOI API to search topic text or creator-name variants, filter publication years, and look up exact normalized DOIs. Creator searches screen candidate names and examine at most 200 candidates. Citation counts come from reported `citationCount` metadata; absent values remain unknown. These counts represent DOI relationships in DataCite Event Data, including citation/reference and supplementary relationships, and are not interchangeable with other citation graphs. An open-access link requires an explicit recognized open license. [REST API](https://support.datacite.org/docs/api), [Citation-count definitions](https://support.datacite.org/docs/consuming-citations-and-references).

## Combined Preprints source

One selection searches three components concurrently: the arXiv Atom API, Europe PMC restricted to `SRC:PPR`, and Crossref restricted to posted-content records explicitly marked `subtype:preprint`. Europe PMC indexes bioRxiv, medRxiv, Research Square, ChemRxiv, and additional preprint servers. Crossref broadens coverage to other DOI-registered preprints. No complete catalogue of every preprint server is claimed. [Europe PMC coverage](https://europepmc.org/help), [Crossref preprint metadata](https://www.crossref.org/documentation/schema-library/markup-guide-record-types/posted-content-includes-preprints/).

Each component considers up to the requested number of accepted records. Crossref examines at most 200 candidates, excluding other posted-content types such as posters and letters. The collection alternates between provider results, deduplicates them, and keeps at most the selected total limit (1–200). A paper found by multiple components retains their original provenance and counts. There is no separate invented “Preprints” citation count or provider total. Select the individual citation index when interpreting metrics.

Topic and author modes use each component's documented search behavior below. DOI mode uses exact matching through Europe PMC and Crossref; arXiv's unsupported DOI mode is reported. Year filters are inclusive. Partial component failures preserve successful records and show their limitations; failure of every applicable component is an error. Searching another source alongside Preprints may find overlapping works, which are conservatively merged. Different preprint/journal DOIs remain separate.

The standalone arXiv choice has moved into Preprints. Older arXiv snapshots and direct refreshes remain supported; editing an old arXiv search in the new dialog selects Preprints.

## API search modes

- **Topic:** Crossref uses bibliographic relevance search; OpenAlex and Semantic Scholar use their paper search endpoints; Europe PMC and PubMed use their native query syntax; arXiv requires all whitespace-separated words across indexed fields. Boolean syntax is therefore not portable across sources. For an advanced biomedical expression, select PubMed or Europe PMC alone.
- **Author:** Names are discovery clues, not verified identity. Crossref searches author metadata and screens candidate bylines for compatible name tokens, allowing initials. It examines at most 200 candidate records; the reported provider total is before screening. PubMed and Europe PMC search the literal name plus surname-first/full-name and surname-initial variants. OpenAlex retrieves works from up to five matching author profiles. Semantic Scholar samples works across up to five matching profiles in rounds. arXiv searches its author field. Profile unions, initials, name changes, group authors, and compound surnames can still create false matches or omissions. Review the authors and exclude unrelated works before interpreting metrics. A name search is not a certified complete publication list.
- **DOI:** DOI prefixes/URLs are normalized and results are retained only when their DOI exactly matches. Crossref and Semantic Scholar use exact record endpoints; OpenAlex, Europe PMC, and PubMed use DOI/identifier filters followed by exact local matching. arXiv does not support this mode. Missing records and unindexed DOIs are possible.

Years are inclusive, from 1500 through the current calendar year plus one. A record with an unknown year is excluded when a year filter is active. Each selected source or combined Preprints collection returns at most the chosen limit (1–200). Provider totals may greatly exceed that limit; metrics apply to the retrieved, included collection. Semantic Scholar author-profile unions do not expose a directly comparable total, so the app leaves it unknown.

## Citation and full-text interpretation

Citation counts are retained with the source record ID and retrieval timestamp. Missing counts are `null`, distinct from a measured zero. PubMed and arXiv never acquire invented citation counts. The same paper can have different counts in different indexes; overlapping counts must not be summed across providers. Changes after refreshing may reflect indexing updates, attribution changes, or coverage changes as well as newly citing papers. See the app's metric definitions for how included records are summarized.

Crossref alone does not establish open-access status in this implementation. For PubMed, a PMC link indicates available full text but does not by itself establish an open reuse license, so it is not counted as confirmed open access. Other sources' explicit open-access flags are used where available. Verify the linked license before sharing full text.

## Reliability and privacy

Requests originate from the desktop app (or the local development server) and go directly to the selected providers. Search text, relevant API credentials, and—for Crossref only—the optional contact email are sent to those providers. No application-hosted search service is involved. Each credential is sent only to its intended provider. Arbitrary query URLs are not accepted; all endpoints are fixed and parameters are URL-encoded. Redirects are rejected to keep credentials on their intended destination. Raw upstream errors and credential-bearing URLs are not included in user-facing errors or source provenance.

API requests have a 15-second timeout and the search has a 60-second overall deadline. Sources run independently with provider-specific pacing. One bounded retry is allowed for temporary server errors or rate limiting. A `Retry-After` longer than five seconds is surfaced to the user instead of retrying before the provider's requested wait. If a source fails after retrieving a page, those records are retained with a partial-results warning. Failures from one source do not discard successful results from another. Saved collections support offline review; a refresh requires a network connection.

## Google Scholar internal collection

Select Google Scholar by itself in New search. The desktop app retrieves result pages internally. Topic mode passes your query; author mode normalizes letter case and spacing in its quoted `author:` field, so case-only variants send identical requests while saved labels retain the original spelling; DOI mode searches a quoted normalized DOI. Years are sent as Scholar search parameters. Unlike exact API DOI lookup, Scholar DOI mode does not certify an exact DOI match. Review the records before interpreting the collection.

The collector reads rendered publication rows and follows actual next-page links, subject to the original query and year filters. After each page is read, the collector waits at least five seconds before requesting the next page, with at most 20 pages and 200 publications. Each load/read has a 30-second timeout. The search has a five-minute active-time budget, paused while the user handles verification. Collection stops at the chosen limit (1–200), the end of results, or an interruption. Repeated record IDs and confidently matched publications are deduplicated. No provider total or complete-career coverage is claimed. **Stop and keep results** saves retrieved records; **Cancel search** discards only the current search.

The capture includes displayed titles, bylines, publication years, snippets, publication links, and citation counts. Byline and journal text may be shortened by Scholar. Snippets are stored separately from abstracts. CSV/JSON preserve that distinction; BibTeX/RIS carry snippets as explicitly labeled notes. Missing or unrecognized citation text remains unknown; an explicit zero is retained as zero. Full-text links do not establish open-access licensing, so Scholar-only captures are not counted as confirmed open access.

A separate temporary browser session handles Scholar. Its window remains hidden during ordinary retrieval and opens if Google requests interactive verification or sign-in. Complete that step yourself, then choose **Resume search**. The app does not solve CAPTCHA, bypass access restrictions, or retry through an access refusal. A timeout, unsupported page, or refused request retains any papers already collected and records the interruption. Refresh starts a new collection and preserves earlier snapshots.

Scholar's help states that bulk access is unavailable and asks automated software to respect its robots policy. This feature is not an official Google API; it cannot guarantee availability. The browser development preview opens Scholar externally and cannot collect its pages. Use the desktop app or import exported bibliographic files. [Google Scholar search help](https://scholar.google.com/intl/en/scholar/help.html).

Subscription interfaces such as Scopus and Web of Science are outside this release's public-data scope. A free website account alone is not evidence of permission or entitlement to automate an API.

## Verification record

Scholar parsing is verified with synthetic result/profile HTML, including hidden rows, absent counts, verification pages, and bounded capture. Native tests use intercepted HTTPS fixtures; those fixtures do not establish live Google availability. A separate v0.4 live check on September 14, 2026 retrieved ten papers and available citation counts from a public topic search while the Scholar window stayed hidden. The app showed page progress, saved the partial collection through **Stop and keep results**, and retained it after reload. This live check used no credentials and stopped after the first page. Live author-profile collection remains unverified; profile parsing passes rendered fixtures.

The mocked integration suite (`tests/sources.test.ts`) verifies input validation, encoded fixed endpoints, pagination, exact DOI filtering, author searches, JSON/Atom/PubMed XML normalization, null-versus-zero citations, safe links, source-specific credentials, partial failures, rate-limit retries, and timeouts.

Live checks on September 14, 2026 used small topic searches and a public DOI, without private API keys:
